Changes
- Preserve a valid access token on app restoration instead of rotating it at every launch. Rotate near expiry. Preserve an expired access token's valid refresh credentials for the explicit restore path; ordinary API consumers still cannot obtain an expired access token.
- Session validation checks whether its token is still current before requesting and before clearing authentication. New login/upgrade restarts validation with its new token. This prevents a stale rejection from clearing a newer session.
- Guard duplicate guest-login calls before the widget rebuild. Guest login replaces old server sessions, so duplicate requests can invalidate a token just returned to the client.
- Reward video preflight checks server session and reward eligibility before display. Authentication rejection during verification stops polling instead of retrying for 60 seconds.
- Reward confirmation uses the server ad counter, not an unrelated increase from daily/badge coins. The server wallet remains authoritative; no client-side coin minting or signature bypass was added.
- Both fullscreen ad formats wait for native disposal before preloading the next ad. UI completion waits at most two seconds; if cleanup is still pending, new loads remain blocked until the actual disposal completes. Review requests are skipped while a post-match ad remains active/cleaning up.
- Fix shop heading text overflow found by the reward screen tests.
