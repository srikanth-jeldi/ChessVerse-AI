compared against release 1.3.26 (293), commit 86eafaa6.

Crash inventory:
1. ARM64 libflutter loaded in x86_64 process: 111 + 28 = 139 events.
   Reported versions 1.3.2–1.3.10 and 1.2.52–1.2.40.
   Existing release fix packages all three ABIs. Verified all 12 native ELF
   headers in the signed 293 AAB, including libapp/libflutter/libdartjni for
   each ABI. Added an upload-workflow check for missing or mislabeled ELF files.
   Old installations are not repaired by changing a new bundle: users need an
   updated release. No evidence here establishes 99% crash-free on the new one.
2. HsdpShimActivity targetPackageName null: 8 events / 8 users, through 279.
   Sample: OnePlus8Pro Android 11, 1.3.13 (279), within first second.
   HSDP 2.1.0 itself appears in the crashing stack. Corrected the misleading
   Gradle comment claiming this pin was a patched fix. Still unresolved.
   The activity is not exported in the current merged release manifest.
   A device model alone does not establish that this is automated traffic.
3. ProxyBillingActivity null PendingIntent: 3 events / 3 users, 257.
   Sample: OnePlus8Pro Android 11. This billing activity is absent from the
   current merged release manifest. Do not disable arbitrary SDK activities
   or suppress crash reporting as a substitute for correcting SDK behavior.

Concrete code defects corrected during this audit:
- Push initialized Firebase asynchronously while analytics and diagnostics
  concurrently accessed Firebase singletons. They could fail before core was
  ready and never enable custom diagnostics in that session. All three now
  await shared Firebase initialization; failed initialization can retry.
- Crashlytics logging/reporting futures could themselves throw into the
  global handler. Reporting now contains its own platform failures.
- Rewarded/interstitial/banner load/show/disposal failures were not consistently
  awaited/caught. They now degrade without aborting the user flow and preserve
  non-fatal diagnostics. Rewarded server verification options finish before show.
- Rewarded load timeout previously left loading=true indefinitely. A retry now
  works, and a late callback from an expired load cannot replace the current ad.
- Concurrent rewarded show callers now recheck ownership after awaiting load.
- Added privacy-safe ad initialization/load/show/dismiss breadcrumbs. These do
  not contain player IDs, auth tokens, ad unit IDs, or user content.
