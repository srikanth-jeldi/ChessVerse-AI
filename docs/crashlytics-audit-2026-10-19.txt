CRASH CAUSES AND STATUS
1. MainActivity.onCreate: 33 events / 8 users, older 1.2.x releases.
   Flutter ARM64 library loaded in an x86_64 process (EM_AARCH64 vs EM_X86_64).
2. SystemLibraryLoader.loadPath: 12 events / 4 users, 1.3.2-1.3.10.
   Same ABI mismatch. Together these account for 45 of 59 crash events.
   Current Gradle explicitly packages armeabi-v7a, arm64-v8a and x86_64;
   build 304 packaging was previously verified. No current-version event
   observed in this audit. Old installed binaries are not changed by a fix.
3. HsdpShimActivity.zzd: 10 events / 10 users, through 1.3.34 (301).
   Google Play HSDP 2.1.0 throws targetPackageName is null when attached.
   Inspected event: OnePlus 8 Pro, Android 11, 19 October 17:19:28.
   Device model alone does not establish that the session is automated.
   Current dependency remains 2.1.0. No verified fix established here;
   do not classify this as resolved or disable arbitrary SDK activities.
4. Hint asynchronous callback after disposal: 2 events / 1 user, 1.3.33.
   Issue f272daa8d9a3129b5f1ea7dde5397719.
   Existing 304 fix checks mounted/request epoch/position before fallback.
5. Save-conflict dialog after game disposal: 1 event / 1 user, 1.3.33 (300).
   Issue 4a1e84ec3ebdacbbbfc8798b2c57abc9.
   Samsung SM-A055F, Android 14, 18 October 09:57:34.
   Decoded matching build-300 ARM64 symbols:
   State.context -> _GameScreenState._writeComputerDraft dialog callback.
   The dialog outlives GameScreen; tapping Back to My Games accesses the
   disposed State.context. Current source still contained this bug.
   FIXED IN SOURCE THIS AUDIT: capture route/navigator while alive; only
   navigate if state and navigator remain mounted and the game route is
   current. This prevents crashes and popping an unrelated replacement page.
   Regression reproduced failure before fix, passed after fix. Also tested
   normal dialog dismissal with the game still mounted.
   NOT YET INCLUDED IN A NEW AAB OR PUBLISHED TO PLAY.
6. ProxyBillingActivity.onCreate: 1 event / 1 user, 1.3.2-1.3.4.
   Billing 8.3.0 attempts getIntentSender on a null PendingIntent.
   No reproduction or verified new fix in this audit; remains unresolved.
